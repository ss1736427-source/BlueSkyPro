# BlueSky Flight Planning
## BSA-002 Взаимодействие модулей системы

---

## 1. Назначение

Документ описывает **взаимодействие всех основных модулей** системы BlueSky Flight Planning и **потоки данных** между ними.

Все взаимодействия выполняются через **BlueSky Core** — единую точку обмена данными и маршрутизации.

## 3. Основной поток миссии
### 3.1. Последовательность действий

┌─────────────────────────────────────────────────────────────────────────────────────────────┐  
│ ПОТОК МИССИИ │  
├─────────────────────────────────────────────────────────────────────────────────────────────┤  
│ │  
│ ШАГ 1: СОЗДАНИЕ МИССИИ │  
│ ─────────────────────────────────────────────────────────────────────────────────────── │  
│ Действие: Пользователь создает новую миссию │  
│ Модуль: Mission Engine │  
│ Результат: Миссия в статусе "Создана" │  
│ │  
│ ↓ │  
│ │  
│ ШАГ 2: ЗАГРУЗКА НАСТРОЕК │  
│ ─────────────────────────────────────────────────────────────────────────────────────── │  
│ Действие: Система загружает настройки: тип БПЛА, профиль миссии │  
│ Модуль: Configuration Manager │  
│ Данные: Паспорт БПЛА, профили оптимизации │  
│ │  
│ ↓ │  
│ │  
│ ШАГ 3: ПРОВЕРКА ОГРАНИЧЕНИЙ │  
│ ─────────────────────────────────────────────────────────────────────────────────────── │  
│ Действие: Проверка маршрута на пересечение ограничений │  
│ Модуль: Regulatory Engine │  
│ Данные: NOTAM, запретные зоны, CTR, TMA, FIR │  
│ Источник: DUM (FAA NOTAM API, Aviation Edge) │  
│ │  
│ ↓ │  
│ │  
│ ШАГ 4: ПОЛУЧЕНИЕ ПОГОДЫ │  
│ ─────────────────────────────────────────────────────────────────────────────────────── │  
│ Действие: Получение и обработка погодных данных │  
│ Модуль: Weather Engine │  
│ Данные: METAR, TAF, GAMET, SIGWX, ветер по высотам │  
│ Источник: DUM (AWC / NOAA) │  
│ │  
│ ↓ │  
│ │  
│ ШАГ 5: ПОСТРОЕНИЕ МАРШРУТА │  
│ ─────────────────────────────────────────────────────────────────────────────────────── │  
│ Действие: Построение ортодромии с учетом рельефа и препятствий │  
│ Модуль: Navigation Engine │  
│ Алгоритм: Гибридный A* + TIG* + Catmull-Rom сплайны │  
│ Данные: Карта, рельеф, препятствия, ветер, ограничения │  
│ │  
│ ↓ │  
│ │  
│ ШАГ 6: РАСЧЕТ ЭНЕРГИИ │  
│ ─────────────────────────────────────────────────────────────────────────────────────── │  
│ Действие: Расчет энергопотребления по маршруту │  
│ Модуль: Energy Engine │  
│ Алгоритм: Динамическое программирование │  
│ Данные: Тип БПЛА, масса, батарея, деградация, погода, маршрут │  
│ │  
│ ↓ │  
│ │  
│ ШАГ 7: РЕКОМЕНДАЦИИ ИИ │  
│ ─────────────────────────────────────────────────────────────────────────────────────── │  
│ Действие: Анализ, оптимизация, формирование рекомендаций │  
│ Модуль: AI Engine │  
│ Алгоритм: Q-Learning + объяснимость │  
│ Данные: История миссий, текущие данные │  
│ │  
│ ↓ │  
│ │  
│ ШАГ 8: ПРОВЕРКА БЕЗОПАСНОСТИ │  
│ ─────────────────────────────────────────────────────────────────────────────────────── │  
│ Действие: Проверка безопасности миссии │  
│ Модуль: Safety Engine │  
│ Данные: Все данные миссии, ограничения, погода, энергия │  
│ Результат: Статус "Безопасно" / предупреждения │  
│ │  
│ ↓ │  
│ │  
│ ШАГ 9: УТВЕРЖДЕНИЕ МИССИИ │  
│ ─────────────────────────────────────────────────────────────────────────────────────── │  
│ Действие: Пользователь утверждает миссию │  
│ Модуль: UI → Mission Engine │  
│ Результат: Миссия в статусе "Утверждена" │  
│ │  
│ ↓ │  
│ │  
│ ШАГ 10: ПОДАЧА ПЛАНА В УВД │  
│ ─────────────────────────────────────────────────────────────────────────────────────── │  
│ Действие: РУЧНАЯ подача плана в УВД (по кнопке) │  
│ Модуль: Communication Engine │  
│ Данные: Пакет полетной документации │  
│ Ответ: Разрешение / Отказ / Запрос изменений │  
│ Режим: ТОЛЬКО РУЧНОЙ │  
│ │  
│ ↓ │  
│ │  
│ ШАГ 11: ОТПРАВКА ПЛАНА НА БПЛА │  
│ ─────────────────────────────────────────────────────────────────────────────────────── │  
│ Действие: Отправка плана полета на БПЛА │  
│ Модуль: Communication Engine │  
│ Протокол: MAVLink │  
│ │  
│ ↓ │  
│ │  
│ ШАГ 12: ВЫПОЛНЕНИЕ И МОНИТОРИНГ │  
│ ─────────────────────────────────────────────────────────────────────────────────────── │  
│ Действие: Сопровождение полета в реальном времени │  
│ Модуль: Monitoring Engine │  
│ Данные: Телеметрия: высота, скорость, курс, координаты, батарея │  
│ Отображение: Flight Chart (карта + телеметрия) │  
│ │  
│ ↓ │  
│ │  
│ ШАГ 13: НЕПРЕРЫВНОЕ ПЕРЕПЛАНИРОВАНИЕ │  
│ ─────────────────────────────────────────────────────────────────────────────────────── │  
│ Действие: При изменении условий (погода, препятствия) │  
│ Модули: Weather Engine, Navigation Engine, Energy Engine, Safety Engine │  
│ Результат: Рекомендация по корректировке маршрута │  
│ Утверждение: Оператор подтверждает или отклоняет │  
│ │  
│ ↓ │  
│ │  
│ ШАГ 14: ЗАВЕРШЕНИЕ МИССИИ │  
│ ─────────────────────────────────────────────────────────────────────────────────────── │  
│ Действие: Посадка, завершение, отчет │  
│ Модуль: Mission Engine → Replay Engine → Database Engine │  
│ Результат: Миссия в статусе "Завершена", данные в архиве │  
│ │  
└─────────────────────────────────────────────────────────────────────────────────────────────┘

## 4. Взаимодействие при изменении погоды в полете

┌─────────────────────────────────────────────────────────────────────────────────────────────┐  
│ ИЗМЕНЕНИЕ ПОГОДЫ В ПОЛЕТЕ │  
├─────────────────────────────────────────────────────────────────────────────────────────────┤  
│ │  
│ 1. Weather Engine фиксирует ухудшение погоды на маршруте │  
│ (по данным AWC / NOAA, обновление каждые 5-10 минут) │  
│ ↓ │  
│ 2. DUM уведомляет Core о критическом изменении погоды │  
│ ↓ │  
│ 3. AI Engine анализирует влияние на маршрут │  
│ (пересчет ветра, безопасность) │  
│ ↓ │  
│ 4. Navigation Engine пересчитывает маршрут │  
│ (учет ветра, рельефа, препятствий) │  
│ ↓ │  
│ 5. Energy Engine пересчитывает энергопотребление │  
│ ↓ │  
│ 6. Safety Engine оценивает риски │  
│ ↓ │  
│ 7. Communication Engine отправляет рекомендацию оператору │  
│ ↓ │  
│ 8. Оператор принимает или отклоняет рекомендацию │  
│ ↓ │  
│ 9. Если принято: │  
│ │ │  
│ ├── Navigation Engine обновляет маршрут │  
│ ├── Energy Engine пересчитывает энергию │  
│ ├── Safety Engine подтверждает безопасность │  
│ └── Core → Monitoring Engine → отправка обновленного плана на БПЛА │  
│ ↓ │  
│ 10. Все действия записываются в журнал (Journal) │  
│ │  
└─────────────────────────────────────────────────────────────────────────────────────────────┘

## 5. Взаимодействие при изменении маршрута пользователем

┌─────────────────────────────────────────────────────────────────────────────────────────────┐  
│ ИЗМЕНЕНИЕ МАРШРУТА ПОЛЬЗОВАТЕЛЕМ │  
├─────────────────────────────────────────────────────────────────────────────────────────────┤  
│ │  
│ 1. Пользователь редактирует маршрут на карте │  
│ (перетаскивание waypoint, изменение высоты) │  
│ ↓ │  
│ 2. UI → Core → Navigation Engine │  
│ ↓ │  
│ 3. Navigation Engine перестраивает маршрут │  
│ (A* → сплайны → плавная траектория) │  
│ ↓ │  
│ 4. Regulatory Engine проверяет ограничения │  
│ (NOTAM, зоны, разрешения) │  
│ ↓ │  
│ 5. Weather Engine проверяет погоду на новом маршруте │  
│ ↓ │  
│ 6. Energy Engine пересчитывает энергию │  
│ ↓ │  
│ 7. Safety Engine оценивает безопасность │  
│ ↓ │  
│ 8. AI Engine формирует рекомендации │  
│ ↓ │  
│ 9. UI отображает обновленный маршрут и анализ │  
│ ↓ │  
│ 10. Пользователь утверждает изменения │  
│ ↓ │  
│ 11. Mission Engine обновляет миссию │  
│ ↓ │  
│ 12. Все изменения записываются в журнал (Journal) │  
│ │  
└─────────────────────────────────────────────────────────────────────────────────────────────┘

## 6. Правила взаимодействия модулей
| № | Правило | Описание | Обоснование |
| :--- | :--- | :--- | :--- |
| 1 | **Нет прямых обращений к БД** | Модули не обращаются напрямую к базам данных других модулей | Обеспечивает независимость модулей и упрощает замену |
| 2 | **Единый центр обмена** | Весь обмен между модулями выполняется через BlueSky Core | Единая точка контроля, журналирования и маршрутизации |
| 3 | **Все события журналируются** | Любое действие или изменение записывается в журнал | Аудит, анализ, обучение, соответствие регуляторам |
| 4 | **Заменяемость модулей** | Любой модуль может быть заменен без изменения архитектуры | Гибкость, эволюционная архитектура, независимые поставщики |
| 5 | **Асинхронная обработка** | Долгие операции не блокируют интерфейс пользователя | UX: интерфейс остается отзывчивым |
| 6 | **Human in Command** | Никаких автоматических изменений без подтверждения | Ответственность за безопасность остается за человеком |
| 7 | **Единый формат данных** | Все модули обмениваются данными в едином формате (JSON/Protobuf) | Упрощает интеграцию и тестирование |
