# ADMINISTRATOR_ENGINEER_TECHNICIAN_AUTHORITY_MODEL_001

## Статус

Закреплённая модель распределения технических функций и допуска персонала в BlueSky PRO.

## 1. Организационная логика

```text
SYSTEM ADMINISTRATOR
        │
        ↓
     ENGINEER
        │
   ┌────┴────┐
   ↓         ↓
TECHNICIAN TECHNICIAN
```

Администратор системы назначает пользователю роль ENGINEER.

ENGINEER в своей зоне ответственности определяет, кто из подчинённых TECHNICIAN допускается к выполнению соответствующих задач по обслуживанию БПЛА.

## 2. TECHNICIAN

TECHNICIAN выполняет назначенные технические работы в пределах предоставленного допуска.

Основные функции:
- техническое обслуживание;
- осмотр;
- диагностика;
- замена компонентов;
- проверка установленного оборудования;
- выполнение иных назначенных технических операций.

TECHNICIAN не получает право на выполнение конкретной технической задачи только из факта наличия роли TECHNICIAN. Допуск определяется в установленной организационной цепочке.

## 3. ENGINEER

ENGINEER является старшим техническим уровнем относительно TECHNICIAN в данной модели.

ENGINEER:
- определяет техническую область ответственности;
- определяет допуск TECHNICIAN к работе с конкретным БПЛА;
- определяет разрешённые виды технических работ;
- определяет, какие подчинённые специалисты могут выполнять соответствующие задачи;
- осуществляет инженерный контроль технической конфигурации и состояния;
- выполняет инженерный анализ и расширенную диагностику;
- работает с инженерной конфигурацией и CUSTOM;
- при наличии соответствующего полномочия выполняет Certification / Release Authority.

## 4. Допуск к работе

Допуск относится к ENGINEER как к функции управления технической компетенцией персонала.

Модель:

```text
ENGINEER
   │
   ├── БПЛА / тип
   ├── оборудование
   ├── вид работ
   └── уровень допуска
          ↓
      TECHNICIAN
          ↓
   разрешённая задача
```

Допуск должен быть ограничен областью, которую определил ENGINEER. Наличие общей роли TECHNICIAN само по себе не открывает все технические операции.

## 5. Сертификация / выпуск

`Certification / Release Authority` относится к уровню ENGINEER и является отдельным полномочием внутри инженерной роли.

```text
ENGINEER
   │
   ├── Engineering
   ├── Configuration
   ├── Analysis
   ├── Planning
   └── Certification / Release Authority
```

Право Certification / Release должно быть явно назначено и ограничено соответствующей областью ответственности.

## 6. Совмещение ролей

Один пользователь может одновременно иметь несколько базовых ролей:

```text
Пользователь
├── PILOT
├── TECHNICIAN
└── ENGINEER
```

Совмещение ролей не требует создания нескольких учётных записей.

## 7. Административная модель

Администратор системы управляет назначением базовых ролей пользователям.

```text
ADMINISTRATOR
      ↓
выбор пользователя
      ↓
назначение ENGINEER
      ↓
ENGINEER
      ↓
назначение технических допусков
      ↓
TECHNICIAN
      ↓
выполнение разрешённых работ
```

Администратор не должен вручную распределять каждую операцию между техниками, если эта функция относится к технической компетенции ENGINEER.

## 8. Принцип интерфейса

В интерфейсе администратора базовое назначение остаётся простым:

```text
Пользователь: Сергей Иванов

РОЛИ
☑ Пилот
☑ Техник
☑ Инженер
☐ Администратор
```

После назначения ENGINEER открывается его технический контур управления персоналом и допусками.

## 9. Связь с конфигурацией БПЛА

Технический допуск должен использоваться совместно с моделью БПЛА, оборудованием и конфигурацией:

```text
ENGINEER
   ↓
область ответственности
   ↓
UAV MODEL
   ↓
CONFIGURATION
   ↓
ALLOWED EQUIPMENT / WORK
   ↓
TECHNICIAN ACCESS
```

Это обеспечивает связь между кадровой моделью, технической конфигурацией БПЛА и выполнением обслуживания.

## 10. Базовый принцип BlueSky PRO

**Администратор назначает роли. Инженер управляет техническими допусками подчинённых специалистов. Техник выполняет разрешённые работы.**
