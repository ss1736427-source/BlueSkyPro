# ADMINISTRATOR_ROLE_CATALOG_001

## Назначение

Единый прикладной каталог ролей пользователя BlueSky PRO. Администратор выбирает пользователя по имени и назначает одну или несколько базовых ролей. Система формирует соответствующий функциональный контур.

## 1. Роли

### 1.1 Пилот (PILOT)

Доступ к функциям, непосредственно связанным с подготовкой, выполнением и контролем полёта в пределах предоставленного эксплуатационного контура.

Основные функции:
- подготовка и проверка полётного задания;
- работа с Flight Chart;
- контроль маршрута и профиля полёта;
- наблюдение телеметрии;
- управление разрешёнными функциями БВС;
- работа с предупреждениями и событиями;
- просмотр доступных данных миссии.

### 1.2 Техник (TECHNICIAN)

Выполняет техническое обслуживание БПЛА и оборудования **только в пределах технического допуска, определённого ENGINEER**.

Основные функции:
- техническое обслуживание;
- осмотр;
- диагностика в пределах допуска;
- замена компонентов;
- проверка установленного оборудования;
- выполнение назначенных технических операций;
- журналирование выполненных работ.

Наличие роли `TECHNICIAN` само по себе не открывает доступ ко всему парку, оборудованию или видам технических работ.

### 1.3 Инженер (ENGINEER)

Старший технический уровень относительно TECHNICIAN.

Основные функции:
- доступ ко всему парку БПЛА в пределах инженерного контура;
- доступ ко всем необходимым техническим данным парка;
- инженерные параметры;
- расширенная конфигурация БПЛА;
- правила совместимости;
- технические модели и характеристики;
- расширенная диагностика;
- работа с конфигурациями CUSTOM;
- контроль технического состояния флота;
- определение технических допусков подчинённых TECHNICIAN;
- Certification / Release Authority при наличии соответствующего отдельного полномочия.

ENGINEER определяет, какие подчинённые техники могут работать с конкретным БПЛА, оборудованием, конфигурацией и видом технических работ.

### 1.4 Администратор системы (SYSTEM ADMINISTRATOR)

Полный административный контур системы.

Основные функции:
- пользователи;
- назначение базовых ролей;
- управление доступом;
- системные настройки;
- справочники и каталоги;
- внешние подключения;
- управление данными и интеграциями;
- аудит и журнал административных действий.

## 2. Совмещение ролей

Роли не являются взаимоисключающими. Один пользователь может иметь несколько ролей.

Пример:

```text
Пользователь
├── PILOT
├── TECHNICIAN
└── ENGINEER
```

Система объединяет функции назначенных ролей без создания дополнительных учётных записей.

## 3. Правило назначения

```text
ADMINISTRATOR
    ↓
USERS
    ↓
поиск пользователя
    ↓
выбор пользователя
    ↓
назначение ролей
    ↓
СОХРАНИТЬ
    ↓
формирование функционального доступа
```

Администратор не должен вручную собирать каждую отдельную техническую capability для обычного назначения роли.

## 4. Техническая иерархия допуска

```text
ADMINISTRATOR
      ↓
назначает ENGINEER
      ↓
ENGINEER
      ↓
определяет технические допуски
      ↓
TECHNICIAN
      ↓
выполняет разрешённые работы
```

Администратор отвечает за назначение базовой роли пользователя. Инженер отвечает за технический допуск подчинённых специалистов.

## 5. Интерфейс

Карточка пользователя содержит минимально необходимый набор:

```text
┌────────────────────────────────────┐
│ ПОЛЬЗОВАТЕЛЬ                       │
├────────────────────────────────────┤
│ Имя: Сергей Иванов                 │
│                                    │
│ РОЛИ                               │
│ ☑ Пилот                            │
│ ☑ Техник                           │
│ ☑ Инженер                          │
│ ☐ Администратор системы            │
│                                    │
│             [ СОХРАНИТЬ ]          │
└────────────────────────────────────┘
```

## 6. Принцип отображения

Назначение роли определяет базовый функциональный доступ. Технический допуск TECHNICIAN определяется ENGINEER. Персональная настройка меню определяет только отображение разрешённых функций и не расширяет полномочия.

```text
РОЛЬ
  ↓
ПОЛНОМОЧИЯ
  ↓
ТЕХНИЧЕСКИЙ ДОПУСК / ОБЛАСТЬ
  ↓
ДОСТУПНЫЕ ФУНКЦИИ
  ↓
ПЕРСОНАЛЬНОЕ МЕНЮ
```

Если функция не разрешена назначенными ролями или областью допуска, она не должна становиться доступной только за счёт настройки пользовательского меню.

## 7. Расширение

При необходимости в будущем могут вводиться дополнительные роли или отдельные полномочия. Базовая модель остаётся простой:

**пользователь → роли → полномочия → область допуска → рабочее меню**.
