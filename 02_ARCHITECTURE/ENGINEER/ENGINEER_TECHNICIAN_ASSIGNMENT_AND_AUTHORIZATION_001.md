# BLUESKY PRO — ENGINEER TECHNICIAN ASSIGNMENT AND AUTHORIZATION 001

## Статус
CANDIDATE_FOR_AGREEMENT

## Назначение
Зафиксировать рабочую модель, в которой ENGINEER определяет технический допуск TECHNICIAN и назначает ему конкретные работы, а TECHNICIAN выполняет только разрешённые и назначенные задачи.

## Authority Chain

```text
ADMINISTRATOR
      ↓
назначает базовую роль ENGINEER
      ↓
ENGINEER
      ↓
определяет технический допуск TECHNICIAN
      ↓
назначает конкретную работу
      ↓
TECHNICIAN
      ↓
выполняет работу
```

## Engineer Responsibilities

ENGINEER:

- определяет область технической ответственности;
- определяет, к каким БПЛА и оборудованию допускается TECHNICIAN;
- определяет разрешённые виды работ для TECHNICIAN;
- назначает конкретные работы на текущую смену;
- при необходимости изменяет или отменяет назначение до начала/в процессе выполнения с сохранением трассируемости;
- видит состояние назначенных работ;
- получает уведомление о нормально завершённых работах;
- получает статус и комментарий TECHNICIAN по незавершённым работам или выявленным проблемам.

## Technician Authorization

Наличие роли TECHNICIAN не означает автоматического доступа ко всему парку или ко всем видам технических работ.

Допуск определяется ENGINEER в пределах его полномочий и может быть ограничен по:

- БПЛА или типу БПЛА;
- оборудованию/компоненту;
- виду технической операции;
- уровню допуска;
- установленным ограничениям.

TECHNICIAN не может самостоятельно расширить свой допуск через интерфейс выполнения работы.

## Work Assignment

Назначение работы должно быть связано с конкретным разрешённым исполнителем и областью его допуска.

Перед назначением BlueSky PRO должен обеспечивать проверку соответствия:

```text
TECHNICIAN
   ↓
TECHNICAL AUTHORIZATION
   ↓
UAV / EQUIPMENT
   ↓
WORK TYPE
   ↓
ASSIGNMENT
```

Если требуемая работа не входит в действующий допуск TECHNICIAN, назначение не должно считаться разрешённым.

## Shift Work

Основной рабочий контур TECHNICIAN — список работ, назначенных ему ENGINEER на текущую смену.

Технику не требуется просматривать полный парк, все технические данные или структуру полномочий. На первом экране отображаются только его актуальные задачи и их состояния.

## Task Execution

После выполнения работы TECHNICIAN фиксирует результат непосредственно в назначенной задаче.

### Нормальное завершение

```text
ASSIGNED
   ↓
IN PROGRESS
   ↓
COMPLETED
   ↓
ENGINEER NOTIFICATION
```

При нормальном `COMPLETED` отдельное подтверждение ENGINEER не требуется, если применимая процедура не устанавливает иное.

### Незавершённая работа / Finding

```text
IN PROGRESS
   ↓
NOT COMPLETED / FINDING
   ↓
STATUS + COMMENT
   ↓
ENGINEER SEES
```

TECHNICIAN обязан указать статус и комментарий, если работа не завершена или выявлено состояние, требующее внимания.

ENGINEER видит эти данные и принимает решение только если его вмешательство действительно требуется.

## No Unnecessary Approval

BlueSky PRO не должен создавать обязательный approval step для каждой штатно выполненной работы.

Система должна различать:

- информационное уведомление ENGINEER о завершении;
- ситуацию, требующую инженерного решения.

Это уменьшает административную нагрузку и соответствует принципу минимализма интерфейса.

## State Update

Результат работы TECHNICIAN должен быть связан с техническим состоянием соответствующего БПЛА/оборудования, если данная работа влияет на это состояние.

```text
TECHNICIAN RESULT
       ↓
MAINTENANCE RESULT
       ↓
UAV / EQUIPMENT STATE
       ↓
ENGINEER FLEET VIEW
```

Изменение технического состояния не должно автоматически означать Certification / Release.

## Separation of Authority

ENGINEER управляет техническим допуском и назначением работ.

TECHNICIAN выполняет работу и фиксирует фактический результат.

ADMINISTRATOR управляет базовыми ролями пользователей и не заменяет ENGINEER в ежедневном распределении технических работ, если это относится к инженерной компетенции.

Certification / Release Authority остаётся отдельным полномочием ENGINEER и не возникает из факта выполнения TECHNICIAN назначенной работы.

## UX Principle

Интерфейс ENGINEER должен показывать прежде всего то, что требуется для управления технической работой:

- кто допущен;
- к чему допущен;
- какая работа назначена;
- состояние выполнения;
- где требуется внимание.

Интерфейс TECHNICIAN должен показывать прежде всего:

**«Какую работу мне нужно выполнить сейчас?»**

Детали допуска, история и объёмные технические данные раскрываются по запросу.

## Verification Considerations

Проверить:

- назначение ENGINEER корректно определяет базовую техническую ответственность;
- TECHNICIAN видит только разрешённые ему работы;
- работа не может быть назначена вне действующего допуска;
- назначение связано с конкретным ENGINEER;
- завершённая работа уведомляет ENGINEER без обязательного approval;
- незавершённая работа требует статуса и комментария;
- статус и комментарий доступны ENGINEER;
- результат работы связан с состоянием БПЛА/оборудования, когда это применимо;
- выполнение работы не предоставляет TECHNICIAN новых полномочий;
- выполнение работы не является самостоятельным Release.
