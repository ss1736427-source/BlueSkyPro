# BLUE SKY PRO - PRINCIPLE OF MINIMAL INFORMATION DENSITY AND CONTEXTUAL DISPLAY

## Status
Закреплено как системный UX/UI-принцип BlueSky PRO.

## Основной принцип

BlueSky PRO должна показывать пользователю только ту информацию, которая необходима для выполнения текущей задачи.

**Часто используемое — постоянно доступно. Второстепенное и объемное — в подменю. Информация, которую достаточно контролировать, — внешним индикатором состояния.**

## Контекст подготовки БПЛА

Подготовка БПЛА выполняется на земле. Рабочее пространство подготовки не должно перегружаться информацией, которая не требуется для подготовки конкретного борта.

На рабочем уровне отображаются только готовность БПЛА, необходимые параметры текущей подготовки, состояние критически важных систем и оборудования, предупреждения и отклонения, а также необходимые действия.

## Информационные уровни

### Уровень 1 - постоянно доступная рабочая информация

Данные, с которыми пользователь работает регулярно и которые необходимы для текущей операции.

### Уровень 2 - контекстное подменю

Вторичная, объемная или редко используемая информация: история, расширенная диагностика, ресурсная статистика, события, документы и архивные сведения.

### Уровень 3 - индикаторы состояния

Если пользователю достаточно знать состояние объекта, вместо вывода массива параметров используется компактный индикатор.

## Правило

Информация не выводится только потому, что она существует в модели системы. Она выводится постоянно, если необходима для текущей работы; по выбору, если является вторичной; по запросу, если является подробной; индикатором, если требуется только контроль состояния.

## Контекст пользователя

Плотность информации зависит от роли и текущей задачи. Пользователь не должен получать единый перегруженный экран со всей функциональностью системы.

## Контекст БПЛА

После выбора БПЛА рабочая область сохраняет контекст выбранного борта. Основная информация по оборудованию, с которым инженер работает постоянно, остаётся доступной непосредственно в рабочем пространстве.

## Два БПЛА

При необходимости сравнения двух БПЛА они могут отображаться одновременно. Каждое окно является независимым рабочим пространством со свободным перемещением по вкладкам и собственными функциями.

## Запрет функционального дублирования

Одна функция должна иметь одно логичное место в интерфейсе.

Принцип навигации: **объект → контекст → действие**.

## Первый шаг — формирование задачи

Первый экран взаимодействия с системой предназначен для формирования задачи до перехода в основной интерфейс.

### Компоновка

- В верхней части размещаются логотип BlueSky PRO и заголовок «ФОРМИРОВАНИЕ ЗАДАЧИ».
- Под заголовком располагается одна адаптивная строка ввода/мониторинга текущего запроса пользователя.
- Высота строки увеличивается по мере переноса введённого текста на следующие строки; при достижении установленного предела используется внутренняя прокрутка.
- Ниже строки ввода горизонтально располагается ряд модулей миссии в компактных аккуратных окошках. Внутри окошка размещается **только название модуля**.
- В окошках модулей **не используются иконки, пиктограммы или другие графические значки**, если отдельным решением для конкретного модуля не установлено иное.
- Модули не должны перекрываться виртуальной клавиатурой планшета.
- При появлении виртуальной клавиатуры для неё сохраняется максимально возможная область экрана без потери доступности строки запроса и ряда модулей.

### Состояние модулей при формировании задачи

- Ряд модулей реагирует на содержание вводимого пользователем запроса в процессе его формирования.
- Если система определила, что модуль уже соответствует составляемой задаче, модуль автоматически отмечается **тонкой зелёной рамкой**.
- Зелёная рамка означает соответствие текущей формулировке задачи, а не отдельное обязательное действие пользователя.
- При изменении запроса система повторно оценивает соответствие модулей; состояние модуля может быть снято, если он больше не соответствует сформулированной задаче.
- Модули, которые система считает полезными дополнениями, но которые ещё не применены к задаче, обозначаются мягкой **«дышащей» рамкой**.
- Рекомендованные модули могут сопровождаться кратким описанием при необходимости.
- Пользователь самостоятельно принимает или отклоняет предложенные дополнения.

### Интеллектуальный ввод

Введённый пользователем текст постоянно отображается в рабочей строке. Допускается аккуратное предугадывание следующего слова, однако система не изменяет текст без явного действия пользователя.

По мере анализа запроса система определяет применённые модули и визуально обозначает их тонкой зелёной рамкой.

После завершения анализа система может предложить дополнительные модули. Рекомендованные модули обозначаются мягкой «дышащей» рамкой и сопровождаются кратким описанием при необходимости.

### Завершение первого шага

После окончательного определения задачи система сообщает пользователю:

**«ЗАДАЧА ОПРЕДЕЛЕНА»**

Для завершения первого шага используется **OK**.

Отдельные кнопки «Подтвердить», «Принять» и «Продолжить» на предыдущих этапах не используются.

После нажатия **OK** выполняется переход через согласованную заставку BlueSky PRO в основной интерфейс.

### Закреплённый сценарий перехода

Последовательность первого шага фиксируется как:

**формирование задачи → анализ запроса → автоматическое определение применимых модулей → рекомендации дополнительных модулей → решение пользователя по рекомендациям → окончательное определение задачи → «ЗАДАЧА ОПРЕДЕЛЕНА» → OK → заставка BlueSky PRO → основной интерфейс.**

Переход в основной интерфейс выполняется только после сообщения **«ЗАДАЧА ОПРЕДЕЛЕНА»** и нажатия пользователем **OK**. До этого отдельные кнопки подтверждения или перехода не используются.

### Навигация назад

«Шаг назад» предусматривается только там, где пользователю необходимо вернуться к предыдущему логическому состоянию или восстановить предыдущий рабочий контекст. Постоянная кнопка «Назад» не является обязательной частью минимального интерфейса.

## Основной интерфейс — верхняя панель

Верхняя панель отображает **общее состояние выполняемой миссии группы БПЛА**.

### Состав

Слева направо располагаются отдельные секции:

1. логотип BlueSky PRO;
2. **ETD**;
3. **TOT**;
4. **TRIP**;
5. **ETA**.

Каждый индикатор времени является **самостоятельной секцией**. ETD и TOT не объединяются ни визуально, ни логически.

### Временная логика

Временные показатели верхней панели рассчитываются на основании временных данных конкретных БПЛА, отображаемых в панели БПЛА, с учётом фактического начала и окончания групповой миссии.

- **ETD** — расчётное время начала миссии.
- **TOT** — фактическое время начала миссии, определяемое фактическим взлётом **первого БПЛА группы**.
- **TRIP** — общее время выполнения миссии: от фактического взлёта первого БПЛА до посадки последнего БПЛА группы.
- **ETA** — расчётное время посадки **последнего БПЛА миссии**.

Если в миссии участвует один БПЛА, он одновременно является первым и последним, поэтому расчёт выполняется по его временам.

Верхняя панель не дублирует индивидуальные данные отдельных БПЛА. Она агрегирует их в показатели общей миссии.

## Основной интерфейс — панель БПЛА

Панель БПЛА отображает **каждый доступный к работе БПЛА в отдельной секции**. Панель располагается непосредственно над нижней панелью основного интерфейса.

### Структура секции БПЛА

Секция имеет горизонтальную ориентацию и содержит:

- изображение БПЛА в **левом верхнем/левой части секции**;
- под изображением, по центру левой части, — **бортовой номер и статус готовности**;
- **узел настройки отображаемых параметров** в левом верхнем углу секции;
- вертикальную разделительную черту после левой области;
- выбранные пилотом параметры — справа от разделительной черты, вертикальным столбцом сверху вниз;
- в нижней части всей секции — **одну тонкую зелёную линию-индикатор состояния миссии БПЛА**.

Дополнительные декоративные линии и разделители в секции не используются, чтобы не засорять экран.

### Настройка отображаемых параметров

Для каждой секции БПЛА доступен отдельный инструмент настройки отображения. В нём доступны все данные соответствующего БПЛА, организованные выпадающим списком для выбора.

Пилот самостоятельно выбирает необходимые для работы параметры. Выбранные параметры выводятся в секцию вертикальным списком у правой части секции, начиная сверху.

Порядок параметров соответствует очерёдности их выбора. Уже установленные параметры можно менять местами перетаскиванием.

При клике на отображаемый параметр система предлагает скрыть его. Скрытый параметр не удаляется из доступного набора и может быть снова добавлен через инструмент настройки.

### Размер секций

Секция автоматически масштабируется до читабельного размера в соответствии с объёмом отображаемой информации.

При одновременном отображении нескольких БПЛА размеры секций должны оставаться симметричными и выравниваться по размеру, необходимому самой большой секции.

### Индивидуальные данные и миссия

Панель БПЛА отображает данные **каждого конкретного БПЛА**. Верхняя панель отображает только агрегированное состояние всей миссии.

Индикатор состояния миссии конкретного БПЛА размещается внизу его секции одной тонкой зелёной линией.

## Критические параметры

Для параметров, имеющих критические пороговые состояния, изменение числового значения должно сопровождаться изменением цвета **самой цифры**:

- нормальное состояние — штатное отображение;
- предупреждение — цифра отображается **жёлтым** цветом;
- критическое состояние — цифра отображается **красным** цветом.

Цветовой сигнал применяется непосредственно к числовому значению и не требует дополнительных рамок, линий или отдельных графических элементов, чтобы не увеличивать информационную плотность интерфейса.

Пороговые значения и условия перехода между состояниями определяются для конкретного параметра в соответствующей технической логике системы. Сам UX-принцип фиксирует именно способ визуального отображения состояния.

## Критерий качества

Рабочий экран считается правильно построенным, если пользователь сразу понимает состояние объекта, видит необходимые для текущей задачи данные, быстро выполняет основное действие и при необходимости может углубиться до полной технической информации.

## Формулировка для системы

> BlueSky PRO не должна заставлять пользователя видеть всю доступную информацию одновременно. Система должна предоставлять полный объём данных и функций через минимальное, контекстное и настраиваемое представление, при котором часто используемая рабочая информация доступна постоянно, вторичная и объёмная информация раскрывается по запросу, а контролируемые состояния отображаются компактными индикаторами.
