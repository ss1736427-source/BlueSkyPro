# SYS-REQ-002 — Формирование и адаптация шаблонов задач

## Requirement

Система должна обеспечивать выбор типовой задачи и формирование универсального шаблона, адаптируемого под конкретный запрос пользователя.

Шаблон не должен рассматриваться как неизменная готовая миссия. Он должен использоваться как исходная модульная конфигурация, которая может быть адаптирована под цель операции, объект, территорию, оборудование, эксплуатационные условия и требования пользователя.

Система должна:

- определять подходящий типовой сценарий на основании структурированной задачи пользователя;
- выбирать соответствующий шаблон задачи;
- формировать начальную конфигурацию шаблона;
- адаптировать шаблон под конкретный объект и территорию;
- учитывать доступное оборудование и capabilities;
- учитывать требования к БПЛА и payload;
- учитывать эксплуатационные ограничения;
- учитывать KPI и критерии требуемого результата;
- учитывать правила безопасности;
- учитывать предусмотренные аварийные сценарии;
- обеспечивать добавление, удаление и изменение необходимых модулей конфигурации;
- обеспечивать получение индивидуальной конфигурации под конкретный запрос пользователя.

## LEGO Mission Concept

Модульная конфигурация должна работать по принципу LEGO:

TASK
→ TEMPLATE
→ CAPABILITIES
→ PAYLOAD
→ CONSTRAINTS
→ SAFETY
→ KPI
→ MISSION CONFIGURATION

Состав модулей должен определяться конкретной задачей.

Необязательные возможности не должны включаться в миссию без необходимости.

Недостающие возможности должны быть выявлены системой и переданы в последующие этапы формирования миссии.

## User Adaptation

Система должна учитывать предпочтения и требования пользователя при адаптации шаблона.

Пользовательский запрос может приводить к изменению:

- состава модулей;
- параметров операции;
- требуемого качества результата;
- ограничений;
- критериев оптимизации;
- требований к оборудованию;
- требований к способу выполнения задачи.

Система должна сохранять связь между исходной задачей пользователя и полученной конфигурацией.

## Operational Learning

При последующей адаптации шаблонов система должна иметь возможность использовать накопленный системой подтверждённый опыт.

Использование накопленного опыта не должно изменять исходные требования пользователя без его уведомления и соответствующей проверки.

Механизм хранения, обработки и распространения накопленного опыта должен определяться отдельными требованиями Mission Memory / Knowledge Engine.

## Template Content

Шаблон задачи должен поддерживать следующие элементы:

- цель;
- алгоритм выполнения;
- capabilities;
- требования к БПЛА;
- требования к payload;
- ограничения;
- KPI;
- правила безопасности;
- аварийные сценарии;
- накопленный подтверждённый опыт.

## Constraints

SYS-REQ-002 не определяет самостоятельно:

- окончательный маршрут;
- окончательный состав флота;
- окончательный выбор БПЛА;
- окончательное решение Safety Engine;
- окончательный режим автономности;
- выполнение реального полёта.

Эти решения выполняются последующими модулями системы.
