# SYS-REQ-004 — Mission Graph

## Requirement

Система должна обеспечивать представление миссии как графа логики поведения системы, включающего последовательности действий, условия, события, ветвления, подтверждения, сопровождение и действия при изменении обстановки.

иссия не должна ограничиваться последовательностью путевых точек.

Mission Graph должен описывать не только геометрическую последовательность перемещения, но и логику выполнения операции.

## Mission Graph Structure

раф миссии должен поддерживать:

- действия;
- условия;
- события;
- ветвления;
- последовательные переходы;
- альтернативные переходы;
- ожидание условий;
- подтверждение оператором;
- изменение состояния миссии;
- реакции на изменение обстановки;
- аварийные переходы;
- завершение отдельных этапов;
- завершение миссии.

аждый элемент графа должен иметь определённые входные условия, выполняемое действие и условия перехода к следующему состоянию, если это применимо.

## Mission Logic

Mission Graph должен позволять описывать поведение системы в зависимости от фактической обстановки.

римеры логики:

CONDITION
→ ACTION

EVENT
→ BRANCH

DETECTION
→ DECISION
→ ACTION

ACTION
→ CONDITION
→ CONTINUE / ALTERNATIVE / ESCALATE

MISSION STATE
→ EVENT
→ NEW MISSION STATE

раф должен поддерживать изменение последовательности выполнения без необходимости перестраивать миссию как простой список waypoint.

## Relation to Mission Configuration

Mission Graph должен формироваться на основании:

- структурированной задачи пользователя;
- выбранной модульной конфигурации;
- требуемых capabilities;
- ограничений миссии;
- определённых правил выполнения.

Целевой поток:

CLIENT INTENT
→ TASK UNDERSTANDING
→ MODULAR MISSION CONFIGURATION
→ REQUIRED CAPABILITIES
→ MISSION GRAPH
→ MISSION

## Adaptation to Situation

Mission Graph должен обеспечивать возможность изменения поведения миссии при изменении условий выполнения.

зменение обстановки может приводить к:

- переходу на другую ветвь;
- изменению выполняемого действия;
- ожиданию;
- запросу подтверждения оператора;
- эскалации;
- прекращению текущего этапа;
- переходу к аварийному сценарию;
- завершению миссии.

зменения логики выполнения должны быть трассируемы до соответствующего условия или события.

## Operator Interaction

Mission Graph должен поддерживать действия, требующие участия оператора.

 зависимости от конфигурации миссии система может:

- продолжать выполнение автоматически;
- ожидать подтверждения;
- передавать управление оператору;
- переходить в определённый сценарий при отсутствии подтверждения.

онкретные уровни автономности и правила их применения определяются отдельными требованиями.

## Constraints

SYS-REQ-004 не определяет самостоятельно:

- конкретный маршрут;
- конкретный тип ;
- окончательный состав флота;
- алгоритмы автономности;
- окончательное решение Safety Engine;
- выполнение реального полёта.

Mission Graph является логической моделью поведения миссии и передаётся последующим модулям для анализа, оптимизации, валидации, симуляции и выполнения.
