# TEST-010 — Формирование и сравнение вариантов оптимизации миссии

## Objective

роверить формирование нескольких вариантов миссии для одной задачи, их сравнение и выбор предпочтительного варианта.

## Preconditions

- BlueSky запущен.
- Mission AI доступен.
- Optimization Engine доступен.
- Mission Validation Engine доступен.
- Сформирована задача и конфигурация миссии.
- пределён профиль оптимизации.

## Test Procedure

1. ередать задачу в Optimization Engine.
2. Сформировать несколько вариантов плана.
3. роверить цель оптимизации каждого варианта.
4. роверить количество .
5. роверить время выполнения.
6. роверить показатель Quality.
7. роверить расход энергии.
8. роверить используемые ресурсы.
9. роверить уровень риска.
10. роверить coverage.
11. роверить communication requirements.
12. роверить результаты Mission Validation.
13. Сравнить варианты по времени.
14. Сравнить варианты по ресурсам.
15. Сравнить варианты по качеству.
16. роверить профили FAST, SAFE, ECONOMIC и HIGH QUALITY.
17. роверить автоматический выбор предпочтительного варианта.
18. роверить объяснение автоматического выбора.
19. зменить профиль оптимизации.
20. овторно сформировать варианты.
21. ыбрать вариант оператором.
22. роверить фиксацию решения оператора.
23. зменить существенный входной параметр.
24. ыполнить повторную оптимизацию.
25. роверить трассируемость изменения до входного параметра.

## Expected Result

- ля одной задачи формируются несколько вариантов миссии.
- аждый вариант содержит цель оптимизации.
- тображается количество .
- тображается время выполнения.
- тображается показатель Quality.
- оступна информация об энергии и ресурсах.
- оступна оценка риска.
- оступны coverage и communication requirements.
- аждый вариант проходит необходимые проверки Mission Validation.
- арианты можно сравнить по времени, ресурсам и качеству.
- Учитываются FAST, SAFE, ECONOMIC и HIGH QUALITY.
- Система может автоматически определить предпочтительный вариант.
- втоматический выбор является объяснимым.
- ператор может выбрать вариант самостоятельно.
- ешение оператора фиксируется.
- ри изменении профиля варианты пересчитываются.
- ри изменении существенного входного параметра выполняется повторная оптимизация.
- зменения трассируются до соответствующего входного параметра.
- ариант с критическим несоответствием не считается допустимым вариантом выполнения.
