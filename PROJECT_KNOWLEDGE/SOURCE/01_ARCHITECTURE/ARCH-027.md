# ARCH-027 — Heterogeneous UAV Fleet and Mission Coordination

## 1. азначение

ARCH-027 определяет архитектуру поддержки одновременно работающих разнотипных  в рамках одной миссии.

Система должна рассматривать  как гетерогенные исполнительные ресурсы с различными возможностями, ограничениями, полезными нагрузками и состояниями.

## 2. сновной принцип

дна миссия может выполняться несколькими  различных типов одновременно.

Тип платформы не должен быть жёстко связан с логикой миссии.

Mission Planner и HUB Core должны работать с унифицированной моделью capability, состояния и доступности .

## 3. Поддерживаемые типы платформ

Архитектура должна допускать как минимум:
- Multirotor
- Fixed-wing
- VTOL
- Hybrid VTOL
- специализированные платформы

обавление нового типа  не должно требовать изменения общей логики Mission Management при наличии совместимого адаптера и capability profile.

## 4. Capability Model

Каждый  должен иметь профиль возможностей.

Профиль должен учитывать как минимум:
- platform_type
- payload_capabilities
- endurance
- range
- maximum_speed
- minimum_speed
- altitude_limits
- operating_environment
- navigation_capabilities
- communication_capabilities
- sensing_capabilities
- landing_capabilities
- current_energy
- current_health
- current_mission_load

## 5. Task Allocation

Mission Planner должен распределять задачи с учётом capability конкретных .

аспределение не должно основываться только на идентификаторе или типе платформы.

ри выборе исполнителя должны учитываться:
- соответствие capability задаче
- текущее состояние
- доступность
- энергия
- дальность
- время выполнения
- полезная нагрузка
- связь
- ограничения воздушного пространства
- риски
- приоритет задачи

## 6. Одновременное выполнение

есколько  должны иметь возможность одновременно выполнять разные части одной миссии.

ример:

дин  выполняет поиск.

торой выполняет подтверждение обнаружения.

Третий обеспечивает ретрансляцию связи.

етвёртый может находиться в резерве.

## 7. Common Mission State

HUB Core должен поддерживать единое актуальное состояние гетерогенной группы.

Состояние должно включать:
- mission_state
- fleet_state
- UAV_state
- task_state
- capability_state
- communication_state
- health_state
- risk_state

## 8. Координация

HUB Core должен обеспечивать координацию распределённых задач между .

зменение состояния одного  должно быть доступно Mission Planner для перераспределения задач.

## 9. Отказ одного 

Отказ или потеря одного  не должны автоматически приводить к потере всей миссии, если оставшиеся ресурсы способны выполнить миссию или её безопасно завершить.

Mission Planner должен иметь возможность выполнить reallocation задач.

## 10. Безопасное завершение миссии

сли полное выполнение миссии невозможно, система должна определить безопасный сценарий завершения.

езопасное завершение может включать:
- завершение критических задач
- возврат 
- посадку
- переход в резервный режим
- передачу задачи другому 
- сохранение результатов
- фиксацию незавершённых задач

## 11. риоритеты

ри распределении ресурсов приоритет должны иметь:

P0 — safety critical

P1 — flight / navigation / C2

P2 — critical mission task

P3 — normal mission task

P4 — secondary task

P5 — background / analytical task

## 12. езервирование

ля критических задач система должна поддерживать резервный исполнитель, если это предусмотрено mission profile.

езервный  должен иметь достаточную capability для выполнения назначенной задачи.

## 13. езависимость от платформы

Mission logic не должна содержать жёстких зависимостей от конкретного автопилота, производителя или физической платформы.

нтеграция конкретного  должна выполняться через адаптер платформы и capability profile.

## 14. асштабирование

рхитектура должна позволять увеличивать или уменьшать количество одновременно участвующих  без изменения базового Mission Management.

## 15. Связь с HUB

етерогенная группа должна взаимодействовать через HUB Core.

азовая схема:

Mission → HUB → Task Allocation → UAVs

UAVs → HUB → Common Mission State

HUB → Mission Planner → Reallocation

## 16. езопасность и отказоустойчивость

отеря связи с отдельным  должна обрабатываться независимо от состояния остальных участников группы.

аждый  должен иметь определённую стратегию поведения при потере связи, отказе или исключении из миссии.
