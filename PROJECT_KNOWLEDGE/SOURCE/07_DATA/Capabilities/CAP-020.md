# CAP-020 — Mission Reporting

## Purpose

Provide structured reporting of mission definition, execution, deviations, outcomes and supporting evidence.

## Description

Mission Reporting shall assemble reports from authoritative and traceable data without changing operational state.

## Inputs

- mission;
- mission revision;
- configuration;
- schedule;
- execution history;
- telemetry references;
- events;
- audit records;
- planned/simulated/actual outcomes;
- deviations;
- recovery;
- evidence.

## Outputs

- mission report;
- execution summary;
- outcome summary;
- deviation report;
- evidence references;
- compliance information where authorized.

## Preconditions

- required source data available;
- data lineage preserved;
- applicable report definition available.

## Constraints

- data availability;
- access permissions;
- retention;
- privacy;
- report format.

## Dependencies

- Data Architecture;
- Audit;
- Observability;
- Mission History;
- Execution;
- Outcome;
- Compliance.

## Algorithms

Report aggregation and presentation algorithms are not fixed at architecture level.

## Safety Constraints

Reporting shall not modify authoritative mission, execution, safety or audit state.

Incomplete evidence shall be clearly identified.

## Interfaces

- mission data interface;
- execution interface;
- audit interface;
- evidence interface;
- data lineage interface;
- export interface.

## Performance

Report generation latency shall be defined according to report type and data volume.

## Verification

Verification shall cover:

- complete report;
- incomplete evidence;
- missing telemetry;
- conflicting evidence;
- historical revision;
- planned/simulated/actual separation;
- access restriction;
- export integrity.

## Rationale

Mission Reporting provides an evidence-oriented presentation layer over authoritative mission history and does not become an operational authority.
