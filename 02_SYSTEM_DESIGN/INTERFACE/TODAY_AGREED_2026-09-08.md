# BlueSky PRO — Сводка согласованных решений за 2026-09-08

## 1. Верхняя панель — USER

Обязательно отображаются:
- Имя;
- Фамилия;
- Фото;
- роль: Пилот.

Остальная информация скрыта и открывается по клику на область USER.

USER предназначен для редактирования карточки пользователя, включая фото.

Вход по логину и паролю выполняется в начале работы с системой; далее авторизация автоматически применяется там, где требуется.

Все действия пользователя в системе маркируются его именем для идентификации в журнале действий.

## 2. Верхняя панель — Battery

Отображается состояние батареи планшета.

Если интерфейс закрывает системное меню планшета — заряд отображается в верхней панели BlueSky PRO.

Если системное меню планшета не закрыто интерфейсом — отображение батареи в верхней панели скрывается.

## 3. Статус миссии

Статусная область показывает краткое состояние:
- подготовка;
- готовность;
- изменение миссии;
- восстановление миссии;
- завершение миссии;
- прерывание миссии.

По клику на область выводится описание текущего состояния и необходимые дальнейшие действия.

Автоматическая модификация выполняется по умолчанию, если вмешательство пилота не требуется.

После автоматической модификации: `МОДИФИЦИРОВАНО`.

После автоматического восстановления миссии: `ВОССТАНОВЛЕНО`.

После завершения миссии: `ЗАВЕРШЕНО`.

После прерывания: `ПРЕРВАНО` с выводом информации пилоту для подтверждения. После подтверждения пилота уведомление закрывается.

Принцип минимализма: после действий пилота информация уведомления скрывается.

## 4. ETD — назначение времени вылета

Для работ по плану доставки грузов, где составлено расписание доставок из точки А в точку В, плановое время автоматически заносится в `ETD`.

Для иных работ, не связанных с расписанием, базовое время формируется автоматически:

`ETD = время входа в систему + время подготовки к полёту по умолчанию (15 минут)`.

Пилот может изменить ETD вручную при более ранней готовности к полёту. По клику на область времени открывается меню:

`Коррекция времени → OK`.

После подтверждения меню закрывается.

При автоматизации подачи плана в ЕСОРВД время может подставляться из соответствующего поля плана полёта. При автоматической подаче в план полёта устанавливается время, назначенное и проверенное пилотом.

## 5. Коррекция базового времени подготовки

Базовое время подготовки — `15 минут`.

Система может корректировать предлагаемое время подготовки на основании статистики фактического времени, затраченного на подготовку.

Предложение коррекции времени на подготовку рейса требует обязательного подтверждения оператора.

## 6. Изменение расписания

При изменении времени в расписании система предупреждает пилота и показывает новое время.

Пилот подтверждает новое время → время корректируется.

За одну минуту до планового вылета, если вылет ещё не начат, время отображается жёлтым.

После взлёта цвет времени становится нормальным.

Если вылет не совершен в запланированное время с точностью до минуты, в следующую минуту время становится красным.

При клике на область времени система показывает задержку в минутах.

Цвет времени возвращается к нормальному:
- после фактического взлёта БПЛА;
- либо после назначения нового времени и подачи плана полёта на новое время.

Задержка взлёта фиксируется в журнале.

## 7. CNL

При отмене полёта пилотом и подаче `CNL` в поле времени устанавливаются `--`.

Это требует нового назначения времени вылета пилотом вручную, если пилот остаётся в системе.

При выходе из системы и новом входе данное правило не применяется.

## 8. TOT и этапы учёта времени

Расчёт времени полёта ведётся от фактического времени взлёта `TOT`.

`TOT` фиксируется по факту взлёта, а не по факту нажатия кнопки `START`.

В расчёте также учитывается время подготовки аккумулятора в режиме висения.

## 9. TRIP

Для группы БПЛА:

`TRIP = время от фактического взлёта первого БПЛА до посадки последнего БПЛА.`

Для одного БПЛА:

`TRIP = от начала движения до момента касания.`

По умолчанию БПЛА возвращаются к оператору, где находится передатчик.

В остальных случаях возврат выполняется в назначенный `DESTINATION`.

## 10. Запас энергии миссии

Запас энергии миссии формируется с учётом:
- запаса энергии на начало движения первого БПЛА;
- запаса до посадки последнего БПЛА;
- запасов энергии остальных БПЛА по принципу от начала движения до момента посадки.

На основании этого выполняется расчёт продолжительности миссии с учётом аварийного возврата по логике построения аварийного возврата.

## 11. Панель БПЛА — идентификация

Над квадратным изображением БПЛА отображается компактная строка:

`SKYMASTER № 2`

Название и порядковый номер находятся в одной строке.

Порядковый номер БПЛА в ряду используется как идентификатор для визуальной связи с картой: по номеру пилот определяет конкретный маршрут, положение и принадлежность аппарата.

## 12. Панель БПЛА — базовые параметры

По умолчанию отображаются четыре основных параметра:
- Высота;
- Скорость;
- Battery в процентах;
- Двигатели.

Пример:

```text
Высота       80 м
Скорость     42 км/ч
Battery      68 %
Двигатели    ───●── 68 %
```

Пилот может:
- скрыть любой из четырёх параметров;
- вернуть скрытый параметр;
- изменить порядок их отображения;
- заменить их другими выбранными инструментами.

Таким образом, четыре параметра являются набором по умолчанию, а не жёстко обязательными элементами.

## 13. Двигатели

Отображается горизонтальный индикатор оборотов/режима двигателей от минимального до максимального режима.

Фактический режим обозначается линией/маркером на шкале и сопровождается цифровым значением.

## 14. Умные инструменты

Остальные параметры отображаются как компактные умные инструменты.

Пример:

`[Ветер] [Курс] [ETA] [C2] [Камера] [+]`

При клике раскрывается только выбранный инструмент. Остальные остаются компактными.

`+` открывает выпадающее меню выбора инструментов для отображения на панели БПЛА.

Наиболее часто востребованные инструменты находятся сверху списка настроек.

Оборудование, необходимое для разных задач, также учитывается при выборе и приоритизации инструментов.

## 15. Автоматический подбор инструментов

Система автоматически подбирает отображение в зависимости от:
- выполняемой миссии;
- роли каждого БПЛА в миссии;
- необходимого для задачи оборудования;
- частоты использования инструментов.

Цель — вывести самый необходимый минимум и не загромождать поле интерфейса.

```text
ТИП МИССИИ
      +
РОЛЬ БПЛА
      +
НЕОБХОДИМОЕ ОБОРУДОВАНИЕ
      +
ЧАСТОТА ИСПОЛЬЗОВАНИЯ
      ↓
МИНИМАЛЬНЫЙ НАБОР ИНСТРУМЕНТОВ
      ↓
ПАНЕЛЬ БПЛА
```

## 16. Адаптивное окно БПЛА

Окно БПЛА автоматически подстраивается под объём информации.

Если информации немного — окно компактное.

При увеличении объёма информации окно может увеличиваться до допустимого размера рабочей области.

Постоянная область прокрутки не используется как основной способ размещения информации.

Для большого объёма применяются компактные умные инструменты с локальным раскрытием только нужной информации.

Критически важные параметры не должны становиться недоступными из-за переполнения.

## 17. Изображение БПЛА

Изображение автоматически подтягивается из карточки БПЛА/базы конфигурации.

Приоритет:
1. индивидуальное изображение конкретного БПЛА;
2. изображение модели БПЛА;
3. нейтральный placeholder при отсутствии изображения.

Изображение хранится локально для работы без внешнего подключения.

```text
ADMIN
  ↓
БАЗА БПЛА
  ↓
ИЗОБРАЖЕНИЕ
  ↓
ПАНЕЛЬ БПЛА
```

## 18. Завершение миссии отдельным БПЛА

После завершения миссии конкретным БПЛА:
- его окно становится неактивным и визуально серым;
- линия состояния миссии заменяется сообщением `ЗАВЕРШЕНО`;
- информация в окне сохраняется для идентификации аппарата и контроля результатов.

Все пункты настоящего документа отражают согласованные на текущем этапе решения и имеют статус `AGREED`.
