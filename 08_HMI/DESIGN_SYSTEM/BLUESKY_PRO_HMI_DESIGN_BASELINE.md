# BlueSky PRO — HMI Design Baseline

## 1. Назначение

Единая рабочая точка сборки визуального и эргономического дизайна HMI BlueSky PRO. Документ используется при разработке экранов, компонентов, прототипов и последующей реализации Qt 6 + QML.

## 2. Принцип

Эскиз пользователя является исходным визуальным reference. Он не считается неизменяемой компоновкой. Панели и информационные блоки должны быть самостоятельными компонентами, допускающими перемещение, изменение размера, скрытие, раскрытие и замену без разрушения остальных частей интерфейса.

## 3. Основные UX-принципы

- Основной путь: Intent → Task → Constraints → Resources → Mission → Validation → Execution.
- Часто используемая информация — постоянно доступна.
- Вторичная информация — в раскрываемых/подчинённых панелях.
- Контролируемые состояния — компактными индикаторами.
- Не допускать функционального дублирования.
- Скрытие параметра меняет только представление; получение, расчёт и контроль данных системой продолжаются.
- Критические состояния и предупреждения не должны становиться недоступными из-за фильтра отображения.
- Для экспертного режима сохраняется расширенный контроль параметров, ограничений, алгоритмов и распределения fleet.

## 4. Архитектура интерфейса

Основные информационные области:

- Header / System Status
- Left Panel
- Center / Flight Chart
- Right Panel
- UAV Status
- Bottom Navigation
- Overlay / Context Panel

Каждая область рассматривается как самостоятельная информационная панель. Состав и порядок панелей могут изменяться на уровне layout.

## 5. Панельная модель

Каждый компонент должен иметь:

- stable UI-ID;
- назначение;
- набор отображаемых данных;
- состояния;
- действия;
- размер min/preferred/max;
- правила скрытия/раскрытия;
- роль пользователя;
- связанные требования;
- статус согласования.

## 6. Основной рабочий экран

Исходная компоновка содержит:

- Mission Templates;
- Flight Chart;
- Mission Analysis;
- Instruments;
- ATC / Communication;
- UAV Status;
- Header telemetry;
- Bottom Navigation.

На стадии UX-rework допускается перераспределение этих функций между панелями.

## 7. Эргономическая цель

Приоритеты:

1. карта и текущая задача;
2. состояние миссии;
3. состояние БВС;
4. связь/C2;
5. критические предупреждения;
6. необходимые действия оператора;
7. вторичная аналитика;
8. настройки и диагностика.

Лишняя информация не удаляется из системы — она переносится в соответствующий контекст.

## 8. Связь с разработкой

Figma используется как рабочая среда UX/UI. SVG используется для векторных assets и трассировки. Финальная реализация — Qt 6 + QML.

## 9. Статус

DRAFT_FOR_AGREEMENT. Конкретные размеры панелей, окончательная палитра, окончательные шрифты и утверждённый logo asset подлежат отдельной проверке.
