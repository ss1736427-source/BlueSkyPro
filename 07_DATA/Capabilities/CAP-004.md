# CAP-004 — Tracking

## Purpose

Maintain the estimated state and identity of mission-relevant entities over time.

## Description

Tracking shall correlate observations across time and provide current track state for dependent mission capabilities.

## Inputs

- detections;
- observations;
- previous track state;
- platform/navigation state;
- mission context.

## Outputs

- track identity;
- track state;
- estimated position/motion;
- track validity;
- track history.

## Preconditions

- applicable observations available;
- required time and identity information available.

## Constraints

- observation quality;
- update rate;
- processing capacity;
- environmental conditions.

## Dependencies

- Detection;
- Perception;
- Navigation;
- telemetry/data processing.

## Algorithms

Tracking algorithms are not fixed at architecture level.

## Safety Constraints

Lost or uncertain tracks shall not silently be represented as confirmed current tracks.

## Interfaces

- Detection interface;
- Perception interface;
- Navigation interface;
- track output interface.

## Verification

Verification shall cover:

- stable target;
- moving target;
- intermittent observations;
- lost target;
- reacquisition;
- duplicate observations;
- conflicting observations;
- degraded processing.

## Rationale

Tracking separates temporal state estimation from individual detection implementations.
